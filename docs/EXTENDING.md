# Extending Paper2ALE

## Add a task family

A task-family module owns scientific materialization and trusted evaluation.
It exposes:

```python
def build_task_files(
    project: dict,
    task: dict,
    *,
    master_seed: int,
    instances: int | None = None,
) -> list[BuildFile]:
    ...
```

Register trusted code through `paper2ale.task_families.register_task_family`:

```python
register_task_family(
    "my_family",
    build_task_files,
    supported_difficulty_levels=("easy", "medium", "hard", "frontier"),
)
```

The builder must be deterministic and side-effect free: all generated bytes
are returned as `BuildFile` objects rather than written directly. Source/model
content never imports or registers executable plugins.

Use these paths:

- agent: `description.md`, `task_card.json`, `main.py`, `input/...`,
  `software/...`;
- evaluator: `reference/...`, `example/...`;
- author: `author/...`.

The family is responsible for:

- seeded input/reference generation;
- a robust grader that fails closed on malformed output;
- at least one independent successful example;
- task-specific leakage sentinels if needed;
- protocol and evaluator provenance;
- realistic mutant fixtures or mutation descriptions.

Register each publishable task's golden/mutant preparation hook with
`paper2ale.verification.register_task_verification`. An unregistered task can
pass static preflight but remains `publication_ready: false`.

If the family declares difficulty support, resolve the task with
`resolve_task_difficulty`, consume the concrete generator/evaluator values,
and emit the exact result of `make_consumption_manifest` at
`author/difficulty_manifest.json`. Family-specific derived physical parameters
belong in a separate author file. The compiler rejects missing, cosmetic, or
tampered consumption manifests.

Core packaging is responsible for visibility projections, path safety,
manifests, and deterministic archives.

## Add a completion provider

Implement `CompletionProvider.complete(request)`. Responses must contain one
structured object. Provider adapters should preserve:

- normalized messages and output schema;
- model parameters and timeout;
- an idempotency key;
- usage and finish reason;
- a digest of the raw response;
- secret redaction in errors and provenance.

`CommandProvider` is the general hosted-provider bridge. It runs an argv vector
with `shell=False`, writes the normalized request as JSON on stdin, and accepts
JSON on stdout. `ReplayProvider` reproduces exact recorded results offline;
`MockProvider` is for tests.

## Schema evolution

Do not mutate `paper2ale.project/v1` semantics in place. Add a new schema
version and a deterministic migration. A migration must preserve source and
evidence identifiers, record lossy conversions, and have canonical-ID tests.

## Add a projection

Profiles are defined by allowed visibility labels in `packaging.py`. Add new
profiles only when they are true projections of the canonical inventory. Never
introduce a separately maintained task directory; that recreates drift between
participant and evaluator packages.
